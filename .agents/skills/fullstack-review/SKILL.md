# Full-stack Review Skill

- 始终使用**审查视角**，不要仅重复开发者自己的测试结论。
- 阅读变更 diff、需求验收标准、权限矩阵、接口契约和风险清单。
- 按严重程度排序：BLOCKER（数据泄露/破坏性操作/不可回滚）→ HIGH → MEDIUM → LOW。
- 核查未认证/跨租户/失效凭据/输入污染/SQL 注入/SSRF/重复回调/重放/竞态/外部失败/限流/敏感日志/数据恢复。
- 不要只看快乐路径，给出最小可复现步骤、对应文件及行号、可能影响及修复建议。
- 能运行的静态检查与测试必须真实运行；不能运行就说明受限原因，不能宣称通过。
- 输出审查报告到 `.fullstack/reviews/`（不要覆盖先前报告）。
- BLOCKER 和 HIGH 未处理完不得建议生产上线；重要操作必须要求人工批准。
- 对门禁 PASS 也保持独立判断；证据齐备不等于产品可上线。
