# P3｜前后端、接口和错误处理

目标：按最小闭环构建可验证的纵向功能切片。

步骤：
1. 先写接口契约（路径、参数、返回、错误码、幂等、认证、分页/速率）。
2. 先实现一条完整纵向切片：持久化→服务→API→前端→日志→测试，而非一次性堆全部页面。
3. 输入在信任边界校验，权限在服务端执行；禁止依赖隐藏按钮实现授权。
4. 关键写入具幂等性或明确说明不支持；超时/取消/重试/外部失败保留可诊断错误码。
5. 对数据库/外部 API 使用最小权限；无密钥写入仓库或日志。
6. 真实用户交互提供加载态、错误态、空态、无权限态。

交付：`03_api_contract.md`、`03_feature_matrix.md`、`03_error_handling.md`，以及真实代码与测试。

反例：API 返回 200 不等于成功写入或客户有权获得数据。

验收：最少一个垂直功能切片可在隔离测试环境跑通，失败分支有可验证行为。
