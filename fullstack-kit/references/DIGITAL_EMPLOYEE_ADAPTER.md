# 数字员工业务适配规范（示例场景；须与真实需求核对）

适用：普通微信群里客户询问，云端资料位于 WPS / 腾讯文档 / Excel 类服务。此文是“风险检查清单”，不是已确认的系统设计。

## P0 需要确定
- 消息渠道的官方 API 能力、使用条件和账号授权边界；不把个人微信非官方自动化假设为合法、稳定或可运营。
- 谁属于客户/内部人员；报价、订单、库存及个人数据的查询级别如何授权。
- 机器人可答/只草拟/必须人工确认的消息类别。
- 无法读取数据、数据过期、多来源冲突时的默认应对：不推断和不杜撰。

## P1-P3 关键控制
- 消息事件幂等、重复/乱序/丢失检测、追踪 ID、限流、退避、死信队列。
- 数据同步保留来源、版本、更新时刻与过期标记；业务关键报价要记录批准者。
- 服务端授权：群/用户/客户/业务数据之间必须有强绑定，不因模型输出绕过。
- AI 模型只提供草稿和检索意图；实际工具调用、可见字段由确定性权限系统决定。
- 工具不得拥有广泛的“读取所有客户数据”权限。

## P4-P7 必测
- 同名客户、跨群串单、相似订单号、过期价格、数据权限被撤销。
- 云表格 API 429/403/500，重复回调、系统掉线后重试、消息历史重放。
- 模型幻觉、提示词注入、恶意单元格内容、越权查询与脱敏日志。
- 真实客户消息发布前，必须经过明确的人类批准/渠道合规评估及灰度回滚预案。
