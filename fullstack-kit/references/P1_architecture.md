# P1｜架构选型、威胁建模

目标：让需求有可实现且可回滚的架构。

步骤：
1. 梳理系统上下文图、信任边界、第三方服务清单、数据流。
2. 建 ADR（至少两个备选及取舍）：框架、数据库、任务队列、缓存、API 设计。版本/维护成本与团队实际能力都要考虑。
3. 估算关键瓶颈，明确超时重试、幂等键、降级模式、死信处理和人工接管。
4. Threat Model：STRIDE 或等价表，明确资产、攻击面、控制措施与残余风险。
5. 定义何时不应自动执行、何时必须等待人工确认。

交付：`01_architecture.md`、`01_adr.md`、`01_threat_model.md`。

反例：不要为了“先进”直接引入微服务、复杂 Agent 框架或多模型链，而忽略可维护性。

验收：关键异常路径有处理策略，架构决策可追溯。
