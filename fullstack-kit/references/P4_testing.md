# P4｜自动化测试与负面场景

目标：建立能独立重跑的质量证明。

步骤：
1. 需求→测试追踪：核心逻辑单元测试、服务/数据库集成测试、关键业务端到端测试。
2. 增加权限、无效输入、并发、重复请求、重放、超时、外部依赖失败、脏数据等负面测试。
3. 测试隔离：固定时钟、隔离数据库、可重复测试数据；避免测试触及生产。
4. 用 `run_check.py` 运行当前项目真实的测试及 lint 命令，保留退出码和日志哈希。
5. 不能只凭覆盖率断言业务正确；测试缺口必须记录。

交付：`04_test_plan.md`，真实 `test` 和 `lint` 执行证据。

反例：只检查函数是否返回字符串，无法证明角色有权看到某订单。

验收：测试及 lint 退出码为 0 且日志完整；否则 BLOCKED。
